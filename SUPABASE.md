# Админка «Ленты» — настройка

Один раз на 10 минут. После этого посты добавляются на `/admin` с любого
устройства, включая телефон.

Пока это не сделано, сайт работает как раньше: «Лента» показывает
образцовые посты из кода, а `/admin` говорит, что настроить.

---

## 1. Завести проект

1. Зайти на **supabase.com** → `Start your project` → войти через GitHub.
2. `New project`.
   - **Name** — `sharidlyadushi`
   - **Database Password** — придумать и сохранить в надёжном месте.
     Он нужен только для прямого доступа к базе, в сайте не используется.
   - **Region** — `Central EU (Frankfurt)`, это ближайший к Ярославлю.
3. Подождать пару минут, пока проект поднимется.

## 2. Создать таблицу и папку для снимков

Слева **SQL Editor** → `New query` → вставить целиком содержимое файла
[`supabase/schema.sql`](supabase/schema.sql) → `Run`.

Должно ответить `Success. No rows returned` — так и надо.

## 3. Завести себе вход

Слева **Authentication** → `Users` → `Add user` → `Create new user`:

- почта и пароль — ваши, ими будете входить в админку;
- галочку **Auto Confirm User** включить, иначе Supabase будет ждать
  подтверждения по почте.

> Регистрация с самого сайта закрыта: пользователей заводят только здесь.
> Так посторонний не сможет создать себе доступ.

## 4. Положить ключи в сайт

Слева **Project Settings** → `API`. Понадобятся два значения:

- **Project URL** — вида `https://xxxxx.supabase.co`
- **anon public** — длинная строка (именно `anon`, **не** `service_role`)

Создать в корне сайта файл `.env` (рядом с `package.json`):

```
VITE_SUPABASE_URL=https://xxxxx.supabase.co
VITE_SUPABASE_ANON_KEY=вставить_сюда_anon_public
```

Перезапустить `npm run dev` — переменные читаются только при старте.

> Ключ `anon` публичный по замыслу: он всё равно виден в собранном сайте.
> Данные защищает не он, а правила доступа из `schema.sql` — читать посты
> может любой, писать только вошедший. Ключ `service_role` в сайт класть
> **нельзя никогда**: он обходит все правила.

## 5. Проверить

Открыть `/admin`, войти почтой и паролем из шага 3, нажать
**Новый пост**, добавить фотографии и сохранить. Пост появится на `/feed`.

---

## Когда сайт будет выложен в интернет

Те же две переменные надо задать в настройках хостинга (Vercel, Netlify,
Cloudflare Pages — раздел `Environment Variables`). Файл `.env` в
репозиторий не попадает, он только для работы на своём компьютере.

## Про фотографии

- Размеры кадра админка снимает **при загрузке** и кладёт в базу вместе с
  адресом. На них держится раскладка коллажа, поэтому снимать их
  заранее — правильно: иначе страница на мгновение считала бы кадр
  горизонтальным и потом перестраивалась.
- **Порядок кадров = раскладка.** Первый обычно становится самым крупным.
  Если коллаж вышел неудачным, порядок меняется стрелками в форме, а
  результат сразу видно в блоке «Как это увидят на сайте».
- В посте показываются первые 5 кадров, остальные прячутся под плашку
  «+N» — по клику открывается вся серия. Так пост всегда помещается в
  экран.
- Бесплатный тариф даёт 1 ГБ под снимки. При 300–500 КБ на кадр это
  порядка двух-трёх тысяч фотографий.
